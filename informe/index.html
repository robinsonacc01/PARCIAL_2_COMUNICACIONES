Arquitectura

El tráfico del navegador entra solo por Nginx. La base de datos vive en backend_net y no tiene salida hacia el host.

Desplegar paso a paso (desde cero, en otro equipo)

  1. Instalar Docker

    Windows o macOS: instalar Docker Desktop y dejarlo abierto. Linux: instalar Docker Engine y el plugin Compose.

    docker --version
docker compose version

    Ambos comandos deben mostrar una versión.

  2. Instalar Git y clonar el repositorio

    git clone https://github.com/robinsonacc01/PARCIAL_2_COMUNICACIONES
cd PARCIAL_2_COMUNICACIONES

  3. Crear el archivo de variables

    Copia el ejemplo. Trae las credenciales por defecto para que la prueba sea inmediata.

    # Linux / macOS / Git Bash
cp .env.example .env

# Windows PowerShell
Copy-Item .env.example .env

  4. Verificar que el puerto 80 esté libre

    Nginx publica el puerto 80. Si otro programa lo usa (IIS, Apache, Skype), ciérralo antes de continuar.

  5. Levantar los cinco contenedores

    docker compose up -d

    La primera vez descarga las imágenes, así que necesita internet y puede tardar varios minutos.

  6. Esperar la inicialización

    Joomla se instala solo y Jupyter instala sus librerías de Python al arrancar. Dale entre 2 y 5 minutos.

    docker compose ps
docker compose logs -f joomla jupyter

    Cuando postgres_db aparezca como healthy y los demás como Up, continúa.

  7. Abrir los servicios

    Abre estas direcciones en el navegador del mismo equipo.

ServicioDirecciónAcceso
Informe (esta página)http://localhost/Libre
Joomla (portal)http://localhost/index.phpLibre. Administración en /administrator con las credenciales de .env
Grafanahttp://localhost/grafana/Lectura anónima. Edición con GRAFANA_ADMIN_USER y GRAFANA_ADMIN_PASSWORD de .env
Jupyterhttp://localhost/jupyter/Token JUPYTER_TOKEN de .env

Verificar que todo funciona

  1. Generar tráfico en Joomla

    Abre http://localhost/index.php y navega por varias páginas del sitio.

  2. Revisar Grafana

    Entra a http://localhost/grafana/, abre el dashboard cargado y comprueba que hay al menos dos gráficas con datos. Actualiza después de navegar Joomla para ver los cambios.

  3. Ejecutar el cuaderno en Jupyter

    Entra a http://localhost/jupyter/, abre la carpeta work, abre analisis_datos.ipynb y ejecuta todas las celdas (Run → Run All Cells).

  4. Comprobar la segmentación de red

    docker ps
docker exec joomla_cms getent hosts database
docker exec nginx_proxy ping -c 2 database

    Solo Nginx publica puerto. Joomla resuelve database por el DNS interno de Docker. Nginx no alcanza la base de datos, porque no comparte red con ella.

Acceder desde otro dispositivo de la misma red

Después de desplegar en un equipo (el host), otro celular o computador de la misma red Wi-Fi puede abrir los servicios usando la IP del host en lugar de localhost.

  1. Obtener la IP del host

    # Windows
ipconfig
# Linux
hostname -I
# macOS
ipconfig getifaddr en0

  2. Permitir el puerto 80 en el firewall del host

    En Windows, acepta la regla cuando Docker lo pida o crea una regla de entrada para el puerto TCP 80.

  3. Abrir desde el otro dispositivo

    Por ejemplo http://192.168.1.50/ para este informe y http://192.168.1.50/index.php para Joomla, cambiando la IP por la del host.

Grafana tiene configurada la URL raíz como http://localhost/grafana/. Desde otro dispositivo puede cargar la página pero redirigir a localhost. Para esa prueba, cambia GF_SERVER_ROOT_URL en docker-compose.yml por la IP del host y ejecuta docker compose up -d otra vez.

Modelo OSI en la solución (resumen)

CapaQué ocurre aquí
7 AplicaciónHTTP entre navegador y Nginx. Nginx reenvía con Host, X-Forwarded-For y X-Forwarded-Proto. Jupyter usa Upgrade para sus WebSockets. Joomla habla el protocolo cliente/servidor de PostgreSQL.
4 TransporteTCP: 80 en Nginx, 5432 en PostgreSQL, 8888 en Jupyter, 3000 en Grafana.
3 RedDireccionamiento IP separado en frontend_net y backend_net. El DNS embebido de Docker (127.0.0.11) resuelve nombres de servicio. El kernel del host aplica reenvío y NAT para el puerto publicado.
2 EnlaceCada contenedor tiene una interfaz virtual (veth*) conectada a un puente (br-*). ARP resuelve MAC entre contenedores del mismo bridge.

Problemas frecuentes

Joomla muestra error o no carga al principio

Se está instalando. Espera unos minutos y revisa docker compose logs joomla.

Jupyter abre pero dice «Kernel connection error»

Revisa que Nginx tenga proxy_set_header Upgrade $http_upgrade; y Connection "upgrade" en la ruta de Jupyter.

El cuaderno falla al importar psycopg2 o pandas

Jupyter todavía está instalando librerías. Espera a que docker compose logs jupyter muestre el servidor listo y vuelve a ejecutar.

«port is already allocated» al hacer up

Otro programa usa el puerto 80. Ciérralo y repite docker compose up -d.

Quiero empezar de cero 
docker compose down -v
docker compose up -d

El parámetro -v borra los volúmenes, incluida la base de datos.
